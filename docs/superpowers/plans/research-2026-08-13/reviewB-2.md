**Ranked findings — Track B feasibility & sequencing (Part I not re-reviewed)**

1. **[blocker] §11.1's shell-wide `backdrop-filter: blur(80px)` breaks every `position:fixed` descendant in the shell — including the mobile focus sheet's keyboard math.** A non-`none` `backdrop-filter` makes the element a containing block for fixed/absolute descendants. `MobileSheet` is a plain `fixed inset-x-0 bottom-0 z-50` div whose `height`/`bottom` are driven by `visualViewport` pixels (`web/src/components/focus-mode/mobile-sheet.tsx:53-70`) — resolved against the shell box instead of the viewport it silently mis-sizes on every keyboard open; same for `key-bar.tsx:294` (`fixed`, `calc(env(safe-area-inset-top)+44px+20px)`), `routes/focus/mobile.tsx:672`, `joystick`, `tour-overlay.tsx:59`. Worse, the repo already documents that iOS WebKit turns modal drawers under **backdrop-filter ancestors** into dead taps (`web/src/components/pwa/a2hs-sheet.tsx:95-98`) — and §11.4 deliberately mounts overlays *inside* that ancestor. Third: the shell root (`layout.tsx:252`) is the outermost element, so there is nothing behind it to blur — the 80px blur is pure GPU cost for zero pixels. **Fix:** paint the substrate as a background/tint layer (opaque `--card` mix, optional `::before` behind content), keep `backdrop-filter` only on floating chrome (the existing `.glass`, `globals.css:246-252`); if a real substrate blur is ever wanted, it must go on a wrapper that contains **no** `fixed` descendants, and B1 must add a mobile-keyboard + keybar regression test.

2. **[blocker] The shell-scoped overlay (§11.4) cannot absorb quick-peek or the mobile Attention card, and B1/B5 send quick-peek to two different destinations.** Quick-peek is a mobile-only Vaul drag-detent half-sheet (`quick-peek-modal.tsx:120-123`, `h-[78vh]`, drag handle) — replacing it with a container-query-sized centred frame deletes the drag idiom on the only pointer type that can open it; meanwhile §16.1 says the 10 raw-Vaul sites (quick-peek among them, deep-1 §9) migrate into `ResponsiveSheet`. Also the §11.4 premise "nav rail and header stay visible" is false on mobile: the focus route strips both navs (`layout.tsx:244,258,263`) and the transcript lives in a body-level `fixed z-50` sheet, so a shell-absolute overlay is occluded. **Fix:** scope the overlay to desktop (`≥md`), declare `ResponsiveSheet` the mobile form of the same state, drop quick-peek from B1 and let it ride §16.1 in B5.

3. **[major] A fixed `--sm-toolbar-h: 44px` (§11.2) and fixed-height chrome slots (§11.7) contradict the repo's documented additive safe-area contract and will reintroduce the notch-clipping bug.** `globals.css:203-221` states the rule explicitly ("the inset has to GROW the header box, never eat into a fixed height"), `focus-header.tsx:355-361` says "Use min-h-11 (NOT h-11)", `safe-header` is 56px min + additive `pt-safe` (files toolbar, `files.tsx:192`), and the nav rail's first row is `h-16` (`layout.tsx:93`). One 44px number aligns nothing and clips titles under the Dynamic Island. **Fix:** ship `--sm-toolbar-min-h` as a *floor* + `pt-safe`; put the crossfading inner in an `inset-0` absolute child of a min-height box; decide 44 vs 56 per column explicitly rather than by token fiat.

4. **[major] §13.2's arrival divider has no data to hang on: delegated prompts are indistinguishable from human prompts in the receiving transcript.** `delegate.rs:57` delivers via `lifecycle::send_text` (the human path), so the receiver's JSONL gets a plain `user` entry; `recall.rs:108-130` `Kind::Teammate` is Claude Code's `<teammate-message teammate_id=…>` fleet envelope (`recall.rs:730-742`), *not* supermux delegation. The only join key is the `delegations` row (`db/audit.rs:52-69` stores `prompt`+`ts`), i.e. a fuzzy text/ts match. And if you instead wrap the prompt in a marker tag, `recall.rs`'s unknown-wrapper catch-all buckets it as `Kind::System` — delegated prompts would vanish from the default "Your prompts" view. Separately, a composer-initiated delegate logs `actor=agent:<from>` (`delegate.rs:63-70`) for a human action. **Fix:** extend `POST /api/agents/delegate` with an explicit `actor` and emit a first-class SSE/chat `delegation` event (id, from, to, ts) that the renderer renders as its own system line + divider; if a transcript wrapper is used, add a `Kind::Delegation` variant to `recall.rs` in the same PR.

5. **[major] §12.8/§13.3's "agents can already invoke the scheduler themselves" is false, so conversational schedule creation has no named mechanism.** The only agent→scheduler endpoint is `POST /api/hook/schedule/done` (`server/src/scheduler/hook.rs:38-41`) — completion only, scoped to the agent's own session; create/list/preview are bearer-only (`http.rs:152` → `protected_router`), and the only supermux-managed agent command is `supermux-task` (board) (`agents/skills.rs:100-110`; the `/schedule` at `skills.rs:74` is just Claude Code's built-in allowlist). Nothing parses "run this every weekday at 8". **Fix:** pick one and budget it in B4 — (a) a managed `/supermux-schedule` command + hook-token-scoped create endpoint mirroring `board/hook.rs`, or (b) a purely client-side composer affordance that opens `ScheduleForm` prefilled (no NL parsing, no server work). Don't ship the system line without the writer.

6. **[major] B1's nav slimming violates the board-removal gate it cites and orphans the onboarding tour.** §17 B1 is titled "nav slimming" (nav = Overview/Focus/Files/Settings) while §12.8/§18 gate board removal on B2's attention rollup + chat reply loop, and B2 separately claims "remove the Board page/**nav**/palette verbs" — B1 as written leaves a live, still-sanctioned triage page (`App.tsx:81`) with no entry point. Removing the Scheduler item also deletes the tour anchor `data-tour="scheduler"` (`layout.tsx:56`), which step 3 targets (`tour-overlay.tsx:35`) — it degrades to a centred card whose copy still says "schedule the routine" from a tab that no longer exists. **Fix:** B1 = scheduler move + `/scheduler`→`/settings#schedules` redirect + retarget/rewrite tour step 3 (`ONBOARDING.tour[2]`, re-anchor to Settings); Board nav removal moves into B2 with the page.

7. **[major] The three-tier attention model can't be computed for most of the roster.** "Unread activity = new transcript entries since last view" (§12.2) depends on the chat data plane, which Track A guards to `provider==='claude' && host_id==null && !team`. Codex/kimi/remote/team rows would silently have no unread tier while sitting in the same list — and §12.5's "chat-mode tiles show the conversation tail" has the same hole. **Fix:** define unread from a provider-neutral signal already on the sessions SSE delta (`updated_at` / `last_activity`, `lib/api/sessions.ts:92,122`) and use `chat_tail` only for the preview *text*; state explicitly what a non-eligible row shows.

8. **[major] Seen-cursor storage is self-contradictory and doesn't fit the prefs mechanism it names.** §12.2 says "client-side seen-cursor", §13.4 says "seen-cursors … sync via `/api/prefs` + SSE". `/api/prefs/:key` is one opaque blob per key with a strict allowlist (`prefs.rs:60-64` — only `overview_layout`, `quick_keys`), whole-value PUT, 50 KB cap (`prefs.rs:70`) and a full-value SSE fan-out on every write (`prefs.rs:110-118` → `use-sessions.ts:194-212`). Opening a session would rewrite and rebroadcast the whole blob, and two devices opening different sessions concurrently clobber each other (last-write-wins). **Fix:** v1 = localStorage cursors (matches §12.2, kills the contradiction); if cross-device is required, add a per-row `PATCH /api/sessions/{name}/seen` rather than a prefs blob — and either way B2 must add the key to `is_known_pref_key`, which the plan never mentions (it only budgets `session_renderer` in Part I §6.1).

9. **[minor→major] "One row component" across overview list / strip / pickers / palette is a god-component trap; the data shapes unify, the behaviours don't.** `SessionRow` (nav + view-transition + jumpIndex, `session-row.tsx:58-128`), `CompactTile` (300 ms dwell → 380×220 tail popover + current-highlight spring, `compact-tile.tsx:26-46`), `SessionPicker` (a **form control**: `{name, display_name, status}`, `allowEmpty`, tolerant of values absent from the list, `session/session-picker.tsx:39-70`), and palette rows (`ApiSession`, uniform height across six row kinds, `[data-highlighted]` keyboard driving, `command-palette.tsx:84-133`) share almost no interaction surface. One component would need ~8 behaviour props plus a density enum. **Fix:** extract a presentational `<SessionIdentityRow>` (mark + title + meta/preview slots + `density`) consumed by three thin interaction wrappers, and explicitly exclude the value-picker from the unification (it isn't a roster row) — otherwise B3's `<EntityPicker>` rewrite churns the same files twice.

10. **[minor] Stale/contradictory text and one motion collision.** §14 still promises palette "navigation (Board/Files/**Scheduler**/Settings)" and lists the "board session-link picker" as an `<EntityPicker>` consumer, both removed by the owner decision in §12.8; §14's typed union keeps `board issue` (fine — API stays) but should say so. Separately, §11.5 puts `<MorphLink>` on nav links while both navs animate the active pill with framer `layoutId` (`layout.tsx:114-118,187-191`): `startViewTransition(flushSync(navigate))` snapshots the DOM while a layout spring is mid-flight on the same element → double animation. **Fix:** update §14 to the four-item nav; in B1 either drop the `layoutId` pill in favour of a VT-named element or exclude the nav from the transition.
